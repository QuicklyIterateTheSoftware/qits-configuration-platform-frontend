A write does not change a running container. qits-platform-deployments reads this application's entries for this environment once per deployment and records the revision it deployed with, so a change arrives with the next deployment.

This table is the overrides, not the whole configuration. A declared default is what the application ships with, and it is stored nowhere here — a row on this page OVERRIDES that default, or holds a key that never had one. Deleting a row does not delete the default; it returns the key to it. What the container actually receives is the two together, which is the @if (env()) { resolved view } @else { resolved view } of one environment, and the defaults themselves are in the declarations. orphaned is worked out at read time against the governing declaration and stored nowhere. It says this row is not reaching the container, for one of two reasons: the declaration does not account for the key at all, or it declares the key a serviceAddress, whose address the platform renders per environment and whose stored row is ignored. Neither is an error, and nothing cleans either up — a key dropped from a declaration leaves its rows exactly where they were, which is what makes a rollback of that declaration cost nothing.
